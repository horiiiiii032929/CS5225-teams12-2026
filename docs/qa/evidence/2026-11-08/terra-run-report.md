The API's public search response does not expose per-route retry eligibility or the internal `NON_ROUTABLE_TOWN` error, so this browser run cannot prove that a retry reaches only eligible cache entries or that permanent Tengah is never requeued. That remains a backend evidence/release gate; do not interpret the client-only retry test as a provider failure or recovery. No load, stress or real provider fault was injected.

Verification of the local fix: `pnpm --filter @flatsplit/web typecheck`, `pnpm --filter @flatsplit/web lint`, `pnpm --filter @flatsplit/web test` (113 tests), and `pnpm build` passed. Typecheck/build printed a TanStack router circular-dependency warning; no test failed. Focused regression coverage includes committed 5xx, TypeError and timeout, and failed/differing confirmation reads. The fix cancels a prior in-flight group read before fetching a fresh one. Unknown non-API exceptions remain honestly unconfirmed; they do not trigger the automatic read. The browser lost-response scenario was repeated against the final local code. Deployment requires the operator's refreshed AWS credentials, followed by deployed browser retest.

## Reproduction

From a checkout with the pinned dependencies and Chromium installed, set `EVIDENCE_ROOT` to a fresh directory with `public/results` and `public/screenshots` subdirectories; run the scripts in `public/scripts` with Node while the working directory is the repository root. Scripts create synthetic test groups and make authorized normal public API writes; use a non-production test environment if these writes are not authorized. They hold invite capabilities only in browser memory, do not print them, and mask the invite input in full-page screenshots. Review screenshots and output before sharing. `terra-run.cjs` performs the 2/5-member positive journeys; `terra-mapping.cjs` compares distinct member outcomes; `terra-recovery.cjs` demonstrates the deployed lost-save defect and real empty results; `terra-conditions.cjs` injects status 503 and delay; `terra-route-retry.cjs` transforms a status response and blocks the retry POST. `terra-failure.cjs` targets a local fixed Vite server on 127.0.0.1:5181 with `/api` proxied to the deployed origin; this requires that server to be started separately. These tests do not represent a human usability study.

Focused browser element captures for readable review: `2-mobile-focused-map.png`, `2-mobile-focused-detail.png`, `focused-keyboard-pin.png`, `focused-real-empty.png`, `focused-lost-save-before.png`, `focused-local-confirmed.png`, and `focused-local-unconfirmed.png`. These were taken directly through Playwright element screenshots, not postprocessed crops. The local confirmed and unconfirmed screenshots are separate controlled cases, not evidence of a deployed fix.

At approximately 01:25 SGT on 8 November 2026, the deployed origin HTML identified `/assets/index-Bx9Ir7cN.js`, `/assets/link-DgDoZIkL.js` and `/assets/index-D6Yp-8nJ.css`. These are observed asset identities, not a cryptographic attestation of the source commit or deployment provenance.

The public scripts use `createRequire` anchored at the current working directory's `package.json`; their syntax passed `node --check` and a dependency import check with `EVIDENCE_ROOT` set loaded Chromium and AxeBuilder successfully. To run the local-fix case, place the included Vite config at the root of a checkout containing commit `50505df` and install its pinned dependencies:

```sh
cp "$EVIDENCE_ROOT/public/scripts/terra-vite.config.mts" ./terra-vite.config.mts
pnpm --filter @flatsplit/web exec vite --config ../../terra-vite.config.mts
```

In another terminal at that checkout root, run `node "$EVIDENCE_ROOT/public/scripts/terra-failure.cjs"`. The local proxy forwards `/api` to the deployed origin; this creates synthetic groups and uses real API writes, so run only when those writes are authorized. Stop the local server and remove the copied untracked config after the run.

A subsequent corrected five-member desktop run also selected the first pin before selecting the second: the detail changed from Clementi to Jurong East, with all five member rows displayed. See `five-corrected.json` and the updated `5-desktop-map.png`; axe reported zero tagged violations, no document overflow and no captured page errors. Thus both two- and five-member desktop pointer selection were checked after correcting the initial repeated-selection setup.

The documented local Vite start command was verified in Chromium after anchoring the web root to the copied config file: HTTP 200, title “FlatSplit · Find your common ground”, visible Create your group form, and no captured page errors. Vite printed an advisory about the extensionless config import; the server started successfully.
